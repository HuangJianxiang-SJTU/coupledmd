00Executive summary

The recommendation in one paragraph, then the numbers.

Submit a transparently filtered v1 — not all 222 systems with known defects. A clean, fully documented subset with an explicit held-back table is a stronger data record than a larger one with silent PBC/completeness problems, and it matches how reviewers read Scientific Data: they reward reusability and honest QC over raw count. Frame the archival repository (DOI/accession) as the stable citable record and the web portal as the access/reuse layer on top of it. Keep every mechanistic finding (bias, selectivity, α5, gateways, partner switching) out of Paper 1 — present them only as "example of potential reuse" vignettes that whet appetite for Paper 2.

01Scope & the two-paper split

A firewall between the resource paper and the mechanism paper.

Paper 1 — this document (Data Descriptor)

  • What data exist & how systems were selected
  • Preparation, force field, simulation protocol
  • Trajectory/metadata organization & formats
  • Technical validation (stability, completeness, replica consistency, annotation mapping)
  • Access & reuse: portal, API, archive
"the dataset enables…" "technical validation indicates…"

Paper 2 — reserved (Mechanistic)

  • GPCR bias, G-protein selectivity
  • Coupling-state structural differences
  • α5 helix behavior, gateway/pocket mechanisms
  • Partner switching, allosteric communication
  • Class/family-level interpretation
"we reveal…" "this explains selectivity/bias"
The novelty-protection rule
Any analysis that would be a result in Paper 2 may appear in Paper 1 only as a validation check or a reuse demonstration — described in methods/technical terms, never framed as a discovery. Example: showing the orthosteric pocket is recovered across replicas = validation. Explaining why a pocket reshapes with coupling state = Paper 2.

Your differentiator vs mdCATH
mdCATH = single domains, temperature series. Yours = multi-chain functional complexes (receptor + G-protein + ligand + membrane) with rich biological annotation (GPCRdb numbering, class, coupling, state). Lean into annotation richness and the web portal as a browsable, filterable interface — that is your unique reuse story.

03Section-by-section manuscript plan

Scientific Data's fixed skeleton, filled for this dataset.

Abstract

Dataset + scale + design + validation + records + portal + reuse, in that order. No discovery verbs. Close on "these data may support future analyses of GPCR/G-protein signaling."

Background & Summary

  • Why GPCR/G-protein complexes matter (drug-target centrality) — brief, cited.
  • Why standardized, large-scale MD of complexes is a gap (contrast GPCRmd single-receptor focus, mdCATH single-domain focus).
  • What this resource provides and who reuses it (ML potentials, allostery methods, benchmark building).

Methods

  1. System selection & sourcing (PDB/template origin, coupling states)
  2. Receptor/G-protein annotation (UniProt, GPCRdb numbering, class, family)
  3. Structure preparation (modeling gaps, protonation, capping)
  4. Membrane + solvent + ion setup
  5. Force field(s), integrator, thermostat/barostat, timestep
  6. Equilibration & production protocol (3 × 500 ns)
  7. Trajectory processing (PBC treatment, alignment, stride/reduced traj)
  8. Metadata & derived-feature generation
  9. Analysis workflows (RMSD/RMSF, pocket detection)

Data Records

Archive first (DOI/accession, license, hierarchy), then portal/API as access layer. Point to Table 2 (structure) and Table 3 (metadata fields). Describe formats explicitly (topology, coordinate, trajectory, reduced, features, pocket, QC, checksums).

Technical Validation

Completeness → stability → replica consistency → annotation/GPCRdb mapping → pocket/orthosteric recovery. Factual tone only. This is where Figs 3 & 4 live.

Usage Notes

Browse / filter / visualize / download / cite workflows; recommended use cases; limitations (held-back systems, force-field/membrane caveats, sampling depth). Honesty here builds reviewer trust.

Data & Code Availability

Repository DOI placeholder; distinguish stable archive vs living portal. Code/notebook repo, license, reproducibility instructions, checksum manifest.

04Language guardrails

Paste-ready phrasings to keep Paper 1 on the resource side of the line.

Use

  • "the dataset enables…"
  • "as an example of potential reuse…"
  • "technical validation indicates…"
  • "these data may support future analyses…"
  • "we provide / we organize / we release…"
  • "consistent with expected behavior…"

Avoid

  • "we reveal…" / "we discover…"
  • "we demonstrate the mechanism…"
  • "this explains selectivity / bias"
  • "the α5 helix drives…"
  • "partner switching occurs via…"
  • family-level mechanistic interpretation

09QC / filtering protocol (defines the clean v1)

The gates behind Fig 1's funnel. Make each gate a stated, reproducible criterion.

Gate 1 · PBC integrity
Reject systems with unwrapped/broken periodic images or membrane discontinuities that survive processing.
Gate 2 · Trajectory completeness
Require all 3 replicas present at full intended length (or a stated minimum); flag short/truncated runs.
Gate 3 · File integrity
Topology + coordinates + trajectory present, readable, checksum-verified, frame counts consistent.
Gate 4 · Stability sanity
No pathological blow-ups (RMSD/energy within expected envelope); membrane intact.
Gate 5 · Annotation completeness
UniProt + GPCRdb + class + G-protein family + state resolved for the system.
State the criteria numerically
Reviewers will ask "what threshold?" Pre-register concrete cutoffs (e.g., minimum retained length, RMSD ceiling for a blow-up flag) so filtering is reproducible rather than subjective.

10Submission checklist

Data record

  • Archive deposited, DOI/accession reserved
  • License chosen (e.g. CC BY 4.0, as mdCATH)
  • Checksums published (Supp Table 3)
  • Portal ↔ archive relationship documented
  • Formats openly specified & readable without proprietary tools

Manuscript

  • No discovery/mechanism verbs (grep the guardrail list)
  • Every figure = a reuser question
  • Held-back systems disclosed + rerun roadmap stated
  • Reuse examples framed as "potential reuse"
  • Limitations section explicit
  • Code repo + reproducibility instructions live

11Suggested execution order

Step 1
Freeze the clean-v1 set: run all 5 QC gates, produce Supp Table 1 & 2.
Step 2
Finalize repository hierarchy + metadata schema; generate checksums (Table 2/3, Supp Table 3).
Step 3
Compute validation metrics: completeness, stability, replica consistency, pocket recovery (Figs 3–4).
Step 4
Build Fig 1 funnel + composition and Fig 2 records/portal panels.
Step 5
Draft text against the section plan; run language-guardrail pass.
Step 6
Deposit archive, reserve DOI, wire portal to the frozen record; final checklist.
One decision to lock early
Fix the minimum-completeness threshold before computing anything — it determines which systems enter every figure and table, so changing it late means recomputing all of them.
